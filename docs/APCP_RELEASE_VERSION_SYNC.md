# AP Cabinet Pro — GitHub Release version sync

## Current source of truth

- Fixed GitHub Release tag: `AP_Cabinet_Pro`
- Uploaded asset name: `AP_Cabinet_Pro_VX.Y.Z.rbz` (exactly three numeric version components)
- Metadata file: `version.json`
- Workflow: `.github/workflows/sync-plugin-release.yml`
- Sync script: `.github/scripts/sync_plugin_release.py`

The sync script considers only completed, non-empty RBZ assets in the published,
non-prerelease fixed-tag release, chooses the highest version and will not
downgrade `version.json`.

## Recommended publishing sequence for the upload Agent

1. Verify and encrypt the RBZ locally.
2. Upload `AP_Cabinet_Pro_VX.Y.Z.rbz` into the existing `AP_Cabinet_Pro` Release.
3. Wait for GitHub API to report the asset as `state: uploaded` and `size > 0`.
4. Trigger GitHub Actions **immediately** via `repository_dispatch` event `apcp-rbz-uploaded`.
5. Wait for **Sync AP Cabinet Pro release version** to complete successfully.
6. Confirm `version.json.latest_version`, `file_name`, and `download_url` equal the uploaded asset.
7. Test the public RBZ download URL and the plugin update notification.

Example with an existing authenticated `gh` CLI session:

```sh
gh api --method POST repos/Aphiphoom/APcncDIY/dispatches \
  -f event_type=apcp-rbz-uploaded
```

Do **not** print a GitHub token in logs or pass it on the command line.
The uploader must have permission to dispatch repository events.

## When uploading manually via the GitHub web UI

GitHub does **not** guarantee a workflow event merely because an asset is added
to an existing Release. Run the `Sync AP Cabinet Pro release version`
workflow manually after uploading, or have an authorized upload Agent call the
dispatch endpoint above.

The `*/15 * * * *` scheduled check is a **fallback**, not a guaranteed
15-minute SLA. GitHub may delay or skip scheduled runs.

## Rollback / safety

- Do not delete an older RBZ as part of syncing metadata.
- The sync script refuses a downgrade to a version below the existing
  `version.json.latest_version`. A deliberate rollback requires an approved
  manual change and a separate release procedure.
- Source code (zip/tar.gz) archives generated by GitHub are unrelated to RBZ assets.
